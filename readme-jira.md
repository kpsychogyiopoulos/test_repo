# HEDNO-LOSSES
  
Developed using the Kedro framework, this project facilitates the preprocessing, training, inference, and clustering stages required for HEDNO’s power theft detection system.
The system ingests data from Datahub tables and is maintained as a project in IBM Cloud Pak for Data as ```dev-datahub-hedno-losses ```.

## Kedro module execution

Having setup and initiated the spark session that we will be using, we inject the spark session to our Kedro pipeline.

This shell is designed to execute the Kedro Pipeline. First it performs a number of steps to prepare for the execution of the Kedro pipeline. Specifically:

- __SHAP & Transformers__: It patches safe_isinstance to prevent SHAP from searching for transformers modules.
- __Tensorflow Blocking__: Blocking of TensorFlow to avoid circular imports in the CP4D environment.
- __LightGBM Patch__: A "monkey patch" to LightGBM to prevent a crash caused by the _n_classes attribute returning None instead of an integer. It replaces the broken attribute with a custom property that safely defaults to a valid value (1 for regressors, 2 for classifiers), ensuring the model can perform comparisons and predictions without triggering a TypeError.
- __Sklearn OneHotEncoder Patch__: A "monkey patch" for the scikit-learn library that adds a missing property to the OneHotEncoder class to ensure compatibility with newer coding standards or specific pipeline requirements.
- __Log Suppression__: A logging "silencer" designed to clean up the console output by suppressing verbose and repetitive messages from the project's main libraries.

Finally:

- __Kedro Execution__: The orchestration engine that initializes the Kedro framework and tunes the Spark environment for distributed execution. It creates a KedroSession using the specific hedno configuration environment and triggers the actual execution of the pipeline.


## Kedro Module Execution — Detailed Breakdown

The “Kedro module execution” shell prepares the runtime environment and then triggers the pipeline run. It is organized into six numbered blocks:

__1. SciPy & Matplotlib compatibility patches__ — Sets Matplotlib to the non-interactive `Agg` backend (required for headless execution). Restores `matplotlib.cm.get_cmap`, which newer Matplotlib versions removed but `scikit-plot` still depends on. Restores `scipy.interp`, which was dropped from modern SciPy but is still referenced by some dependencies. Forces `joblib`/`mlxtend` parallel execution to use the `threading` backend, so background worker threads inherit these patches rather than spawning separate processes that wouldn't have them applied.

__2. SHAP & TensorFlow patches__ — Wraps `shap.utils._general.safe_isinstance` so that any check against a `transformers`-prefixed class path short-circuits to `False`, preventing SHAP from trying to import/introspect the `transformers` library during explainability. Fully blocks TensorFlow by setting `sys.modules["tensorflow"]` and `sys.modules["tensorflow.python"]` to `None` and disabling `USE_TF`/`USE_TORCH`, avoiding circular-import issues seen in the CP4D runtime.

__3. LightGBM recursion-safe patch__ — Replaces `LGBMModel._n_classes` with a custom property that safely defaults to `2` for classifiers and `1` for regressors when the underlying attribute is `None`, preventing a `TypeError` during model comparisons/predictions without triggering infinite recursion.

__4. Scikit-learn OneHotEncoder patch__ — Adds a `feature_name_combiner` property to `OneHotEncoder`, backed by a private `_feature_name_combiner` attribute, for compatibility with code expecting this newer scikit-learn attribute.

__5. Logging configuration__ — Sets `logging.raiseExceptions = False` so logging errors don't interrupt execution. Silences verbose `kedro`, `kedro.io`, `kedro.runner`, `kedro.framework.*`, and `py4j` loggers by raising their level to `WARNING`, stripping their handlers, and disabling propagation. Also suppresses `matplotlib.font_manager` logging and caps any active `RichHandler` at `WARNING`, keeping console output focused on the pipeline's own print statements.

__6. Kedro initialization & run__ — Sets the working directory to the project root and reads `pyproject.toml` to determine the Kedro package name. Calls `bootstrap_project()` and `configure_project()` to register the project with Kedro's framework. If an existing `spark` SparkSession is found in the notebook's namespace, reuses it: sets the log level to `WARN`, applies legacy date/time and Parquet rebase settings for compatibility with older data, and — if present — attaches `hedno_worker.zip` as a dependency package for the Spark executors via `addPyFile`. Finally, opens a `KedroSession` scoped to the `hedno_test` environment and triggers `session.run()`, followed by an explicit `session.run(pipeline_name="preprocessing")` to run the preprocessing pipeline specifically.

> __Note:__ `session.run()` with no arguments only executes whatever pipeline is registered as `__default__` in `pipeline_registry.py` — it does not run every pipeline in the project. The explicit `session.run(pipeline_name="preprocessing")` call that follows is what actually triggers the preprocessing stage; other pipelines (`modelling`, `nlp_clustering`, `nlp_inference`) must be run the same way, by name, in separate calls.
